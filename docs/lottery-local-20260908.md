# 每日抽奖：本地实现与验收

本轮范围：本地开发与测试，不部署生产环境。活动默认关闭，由管理员显式开启。

## 已确认规则

- 北京时间（UTC+8）每天 10:00 开放，最晚当天 23:59:59 结束；每日一次免费机会，不累计，不扣余额。
- 累计有效人民币余额充值实付金额达到 10 元即可参加，与当前余额无关。管理员加款、兑换码、赠送、邀请返利和抽奖奖励不计入，也不会导致真实充值用户被排除。
- 只计已支付、已完成且有支付交易号的订单。已退款订单排除；部分退款按到账额度的退款比例扣减实付人民币金额。待退款订单保守暂停计入。
- 非人民币支付不跨币种累加；有币种快照时以快照为准。缺少币种快照的历史订单仅对明确的人民币支付方式回退，未知方式不计入。
- 中奖档位：1、5、10、20、50、100 额度，另有无奖结果。
- 每日总发放硬上限 100 额度。默认权重（万分比）依次为 `[9552,400,30,10,5,2,1]`，即无奖 95.52%、1 额度 4%、5 额度 0.3%、10 额度 0.1%、20 额度 0.05%、50 额度 0.02%、100 额度 0.01%。基础理论平均每 1,000 次发放 95 额度，不是固定发放量。
- 超出剩余预算的奖品转为无奖，不重新抽取；预算归零结束当天活动。
- 用户页不显示概率、奖池金额或内部预算变化规则，不作固定中奖率或保底中奖承诺。

## 入口和界面

- 顶部金额图标左侧增加红色“抽奖”入口，2.8 秒轻微呼吸动画。移动端保留入口，系统减少动态效果时停用动画。
- 用户页 `/lottery`：奖品、服务器校准的开放倒计时、资格提示、今日结果及最近 30 次个人记录。
- 管理页 `/admin/lottery`：立即生效的活动开关、次日生效的概率设置、日期筛选、当日发放总额、中奖分布和最近 100 条奖励流水。
- 规则变更和操作者记录在 `lottery_config_audits`；当日权重快照保存在 `lottery_days`，不因次日配置更改而改变。

## 后端与数据约束

- 新增迁移 `237_daily_lottery.sql`，新增独立活动开关、规则版本、每日预算、抽奖流水和配置审计表；不改既有支付履约逻辑。
- 用户接口 `GET /api/v1/lottery` 和 `POST /api/v1/lottery/draw` 经过登录、运行模式与面板限流中间件。抽奖请求仅需 `activity_date`，身份始终取自认证上下文。
- 管理接口 `GET /api/v1/admin/lottery`、`PUT /api/v1/admin/lottery/config` 受管理员中间件保护，处理器再次验证管理员角色。
- 使用数据库时钟判断日期和开放时间，避免系统时区配置影响。等待锁后再次核实日期，旧页面不能消耗新一天机会。
- 当日预算行锁串行保护跨实例并发；用户行锁保护余额；用户与日期唯一约束防重复；数据库 CHECK 限制每日已发放不超过 100。
- 密码学安全随机票号由后端生成；前端没有随机开奖逻辑。
- 余额更新、奖励流水、预算扣减和次数增加同事务提交；任一步失败全部回滚。无奖也生成唯一记录。
- 相同用户、同一天重试返回原结果；完成后即使活动关闭或跨天，原日期重试仍可取回结果。奖励成功后清理鉴权与计费余额缓存。
- 用户 DTO 采用字段白名单，不返回权重、剩余预算、随机票号、中奖分布或其他用户信息。
- 奖励流水独立记录余额前后值，不伪装成充值订单，不触发邀请返利，也不产生充值资格。

## 已完成测试

- 穷举全部 10,000 个随机票号，验证概率边界、总权重及理论发放量；验证预算不足直接无奖。
- 北京时间 09:59:59、10:00:00、23:59:59、次日 00:00:00 边界和不同服务器时区。
- 实付 10 元但到账仅 1.4 额度仍符合资格；仅余额被管理员增加不符合资格；退款、外币、订阅订单及未支付凭据排除。
- 40 个同用户并发请求只生成一条流水并增加一次余额。
- 1,000 名用户并发请求，仅发出累计 100 额度，预算、流水合计和余额增量一致。
- 随机源失败回滚；余额更新后的流水写入失败仍整体回滚。
- 超预算转无奖、无奖消耗当日次数、跨天重试、次日规则和配置审计。
- 用户与管理员处理器权限、认证身份绑定、日期校验及用户接口敏感内部字段隔离。
- 前端用户页所有状态、重复点击、响应丢失后的结果恢复、倒计时开放刷新、错误重试及内部概率信息隐藏。
- 管理页参数校验、整数权重提交、开关独立更新和失败后状态恢复；顶部入口位置、呼吸动画和减少动态效果支持。
- 最终前端全量回归 272 个测试文件、1,943 个用例通过，包含管理页新增测试。相关后端单元回归、数据库集成测试（含既有迁移 236 和 API Key 仓储回归）、类型检查、ESLint 与 Go vet 通过。

## 验收边界

测试验证的是应用数据库内的一致性和既有订单字段口径，不替代支付渠道对账。历史缺失币种或支付凭据的订单不会通过人工猜测自动补齐。预算保护并不保证所有奖品在一天内一直可抽取；100 额度奖品仅在当日尚未发放其他额度时有可能发出。
