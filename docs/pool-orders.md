# ModelPort 拼单与独立号池

## 入口与流程

- 用户：`/pool-orders`（拼单大厅）。
- 管理员：`/admin/pool-resources`（独立拼单号池）、`/admin/pool-orders`（拼单管理）。
- 管理员发布长期展示的商品，例如 Plus 账号 2 人团、Pro 账号 3 人团。商品配置包括说明、每席价格、人数、发货后有效天数、拼团有效天数、订阅类型、整团 $ 周期额度、Plus 的 5 小时 / 周额度和个人并发；可编辑及上下架，发布商品不会创建订单。
- 大厅固定展示上架商品、正在拼团的订单和最近 24 小时成团记录。拼团中状态标红为「正在拼团中」；个人已成团与历史记录放在「我的拼单」。
- 用户确认购买商品后，系统创建新订单并扣款购买首席位，拼团截止时间从这次购买开始按配置天数计算。后续成员从正在拼团的订单加入。每次明确购买商品都会发起新团，不自动塞入其他订单。
- 满员后进入「待发货」，记录成团时间和 24 小时发货截止时间，生成管理员站内通知。超时明确标记待办，仍可补发；不自动扣减服务时长或自动退款。
- 管理员在拼单号池沿用原 sub2 账号管理页添加、导入或重新授权账号，选择待发货订单号与可用账号后点击「关联订单并发货」。每个账号同时只有一个有效车次。
- 使用 ModelPort 站内余额购买席位。成团和待发货期间均不发 Key、不计算服务时间；管理员成功发货时，在同一事务为每名成员创建专属 Key、授权专属组和订阅，统一开始计时并生成成员通知。重复发货不重复发 Key，不重置服务有效期。
- 成员从现有「API 密钥」页查看、复制自己的拼单 Key；额度归属始终按成员记录保存，改名、限额设置不能扩大拼单配额。
- 到期或终止后，同一号池账号可开新车。新车使用新资源组、新订阅和新 Key；旧 Key、钱包流水及用量保留。
- 第一版支持 OpenAI HTTP 文本 Responses、Chat Completions 和经 OpenAI 网关转发的 Messages。OAuth 支持复用现有后台刷新机制；客户端需关闭 WebSocket、服务端会话历史、多媒体和上游内置联网工具，发送完整文本历史。客户端本地函数工具可用。

## 独立管理与调度隔离

`pool_resources` 定义拼单资源归属，原账号管理组件以独立数据范围创建、编辑、批量维护账号。底层复用已有 `accounts` 的 OAuth 刷新、上游转发和调度服务，但不把拼单资源放进普通号池列表、普通分组列表或无组的全平台调度候选中。

OAuth 授权、RT / Mobile RT、Codex auth.json / AT、Agent Identity 文件及 PAT 继续使用原有账号接口；拼单模式传递 `pool_scope: true`。新账号、专属组、资源归属和调度事件在同一事务创建。文件导入的匹配更新仅查询同一号池，避免更新普通账号。普通导入维持原有范围。

数据库约束阻止移除拼单账号的分组或更改其平台、普通账号混入拼单组、拼单账号绑定普通组、拼单组开启普通号池回退，以及专属 Key 修改用户、分组或开启自动选组。普通 Key 即使获得拼单分组授权，也不能消费该组资源。停用账号、取消或到期都会在请求入口重新查验，不依赖旧的 Key 缓存状态。

上游凭据只保存在服务端，成员接口不返回账号凭据、其他成员身份或其他成员 Key。此隔离是同一 ModelPort 内的逻辑资源隔离，不是独立部署另一套 Sub2API。

## 公平额度与准确性边界

新商品默认使用 `quota_mode=credits`，在同一 ModelPort `$` 计费体系下按人数均分额度。`plan_type` 明确配置为 `plus` 或 `pro`，不通过商品标题猜测订阅类型。购买席位的余额与调用使用的额度是两本账；调用不再扣钱包余额。

| 商品参数 | Plus | Pro |
| --- | --- | --- |
| `total_credit` | 服务有效期内整车总额度，必须大于零 | 同左 |
| `credit_5h` | 整车 5 小时额度，必须大于零 | 必须为零，不施加此窗口 |
| `credit_7d` | 整车周额度，不低于 5 小时额度、不高于周期总额度 | 必须为零，不施加此窗口 |
| `concurrency` | 个人并发上限 | 同左 |

每席额度为整车对应额度除以人数，保留 8 位小数向下取整，余数不额外给某名成员，也不借用别人未使用的份额。每人另外最多每分钟接受 60 次调用，防止高频微量请求。Pro 跳过平台设置的 5 小时、周额度，并不绕过实际上游返回的错误或可用性检查。

人数、购买价格、服务天数、配额方式、订阅类型和各项额度在首位用户付款时复制成订单快照。修改商品仅影响未来新订单。调用按经官方核对的 OpenAI API Standard 价表核算输入、输出和缓存；所有成员使用同一计量标准，独立于普通中转的渠道定价、个人倍率和 Fast / Flex 档位。长上下文按官方阈值（总输入 > 272,000）对整次请求应用阶梯价。`$` 是站内用量单位，不代表 Plus / Pro 官方订阅额度的美元兑换值；商品中的预算需由运营配置。额度规则锁定在订单；模型价格以当前生效的拼团价表为准，已结算记录不追溯改价。

Plus 的窗口优先对齐账号 `codex_5h_reset_at` / `codex_7d_reset_at`。缺少有效上游时间时，从订单发货时间建立所有成员共享的窗口；旧快照过期时按相同周期推进，后续快照再校正。有效窗口快照已耗尽时提前拒绝新请求。Pro 不依据这些快照设置本地窗口配额。上游未知额度继续显示“未知”。

请求按 UTF-8 输入字节数加协议开销，以及最大输出（未指定时默认 4096 Token）估算 `$` 预占。未知或无法确认价格的模型在请求前拒绝。预占在订单、成员行锁内与个人剩余额度、窗口和并发一起校验，多进程无法抢占另一名成员的份额。待完成请求即使跨过窗口边界，仍占用当前窗口，直至实际结算。

实际用量通过原有计费链路结算，使用已有模型路由，按实际转发模型的拼团 Standard 价格，不信任客户端自报用量。拼单美元结算、订阅用量与原计费去重在一个数据库事务中执行；重复结算不重复扣额。实际 `$` 扣额和使用记录的 `actual_cost` 统一量化到 8 位小数。断线、进程退出或没有可靠用量时保留预占，收到实际用量后校正；超过一小时的遗留预占在下一次请求时转为待核对。

**OAuth/Codex 订阅上游不接受最大输出 Token 参数，单次实际用量仍可能超过预占。系统保留真实用量、结算后拒绝新请求，不宣称零超额硬上限。预占是估算值，实际模型映射、上游包装与隐藏开销也可能产生差额。**

历史 `quota_mode=tokens` 商品和订单继续使用原有 Token / 请求次数及并发规则，不自动把已购买权益换算成美元。历史订单的 `$` 使用记录仅供统计。Token 仍统计互斥的输入、输出、缓存创建与缓存读取量。管理员可以编辑旧商品的配额方式，但只影响后续新订单。

## 拼单使用记录

复用用户现有 `/usage` 页面，不建立第二套成功请求账单。每条拼单记录通过不可变的专属 Key 关联 `pool_order_id`，历史调用也可识别；列表在 Key 名旁标记「拼单 #订单号」，费用处标记「拼单订阅用量」。订单卡片提供按该 Key 和拼单来源过滤的直达入口。

`usage_source=pool|standard` 筛选同时作用于分页记录、统计卡、趋势、模型和分组图表及 CSV 导出。CSV 增加使用来源与订单号。所有查询保留当前用户的归属条件，其他成员的明细不可见。

选择拼单来源时，页面额外显示当前用户最近 100 条「进行中 / 待核对预占」，明确区别已结算费用与暂时保留的额度；此面板不受日期范围筛选影响，可手动刷新。暂缺实际用量的保守扣额不混充成功请求费用，避免总额度与已结算记录无法解释地不一致。

## 余额与退款

- 购买席位：锁定订单和用户余额，扣款、席位、钱包流水在同一事务中提交。重复点击、接口重试不会重复扣款；满员后第三人无法购买。
- 未成团退出：全额退回站内余额。退出后不能再次加入同一车次，但可参加其他车次；商品订单最后一名成员退出后结束空团；到参团截止仍未满员，可自行退出退款或由管理员统一终止退款。
- 管理员终止：未开始全额退款；已开始按剩余服务时长占购买时长的比例退款，最多等于原支付金额。金额保留 8 位小数，只退站内余额。
- 退款流水以成员和退款类型唯一约束去重，重复终止不会重复退款。已接受的在途请求仍按原成员结算，后续请求被拒绝。

本功能使用已有站内余额，不直接新增外部收单或提现退款渠道。发布前需确认运营额度与成团后 24 小时内的发货能力；未自动替换现有普通账号。

## API

所有面板接口沿用既有 JWT、管理员权限、审计及面板限流保护。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/usage?usage_source=pool` | 拼单使用记录；相同筛选适用于统计、趋势和图表接口 |
| `GET /api/v1/pool-credit-holds` | 当前用户最近 100 条未结算或待核对预占 |
| `GET /api/v1/pool-orders` | 大厅、整车额度与自己的席位 |
| `POST /api/v1/pool-orders/:id/join` | 余额购买席位 |
| `POST /api/v1/pool-orders/:id/leave` | 未成团退出退款 |
| `GET /api/v1/admin/pool-orders` | 管理订单列表；不再提供管理员创建订单接口 |
| `GET/POST /api/v1/admin/pool-products` | 商品管理列表 / 发布商品 |
| `PUT /api/v1/admin/pool-products/:id` | 编辑、上下架商品，需携带当前 `version` |
| `GET /api/v1/pool-products` | 上架商品列表 |
| `POST /api/v1/pool-products/:id/purchase` | 提交商品 `version` 与 UUID `request_id`，购买首席位并开团 |
| `POST /api/v1/admin/pool-orders/:id/deliver` | 选择 `resource_id`，绑定已成团订单并发货 |
| `GET /api/v1/pool-notifications` | 管理员待发货通知 / 当前用户的发货通知 |
| `POST /api/v1/pool-notifications/:id/read` | 标记本人可见通知已读 |
| `GET /api/v1/admin/accounts?pool_scope=1` | 原账号表格查询独立拼单范围 |
| `POST /api/v1/admin/pool-orders/:id/cancel` | 终止并退款 |
| `GET/POST /api/v1/admin/pool-resources` | 独立号池列表 / 添加账号 |
| `PUT /api/v1/admin/pool-resources/:id/status` | 启用 / 停用账号 |

新增 `241_pool_delivery.sql`：订单绑定允许为空，增加待发货状态、成团时间、发货期限、账号资源关联与站内通知。历史已开通订单保持原 Key 和有效期；历史尚未成团订单释放预绑定，统一改用成团后发货。站内通知每 30 秒刷新，通知已读按用户持久化；管理员待办发货或终止后自动移出列表。

验证包含：真实 PostgreSQL 事务测试（并发抢席、余额不足回滚、独立并发、Token/次数限制、异步结算去重、退款幂等、过期拦截、号池隔离、账号复用）、HTTP 输入边界、异步上下文保留，以及页面交互、原账号添加/编辑/批量编辑回归和国际化一致性检查。新增验证：成团不发 Key、不计时，24 小时截止时间、发货/取消互斥、重复发货幂等、通知权限、原生创建账号事务与分组不可摘除。独立本地数据库已通过真实 HTTP 登录、发布、成团、通知、原生账号创建、管理范围隔离、权限拒绝、发货和成员 Key 的闭环验收。

新增 `242_pool_products.sql`：商品、订单商品关联、付款请求去重表。旧订单保留，不自动转换为上架商品；管理员需发布自己的正式商品。付款请求在用户内去重，同一请求重试返回原订单；余额不足时订单和扣款全部回滚，商品已变更时要求重新确认，避免扣除用户未确认的价格。

商品流程额外验证：发布无订单、首付开团、并发重试去重、余额不足无残留、商品编辑保留订单快照、上下架与版本检查、按天换算及加入后自动转待发货。

本地预览使用虚拟账号和测试凭据，未调用真实 OpenAI 上游；OAuth 真账号刷新和真实 Token 回报仍需运营账号联调。上线前需按现有流程备份数据库并部署应用及迁移。回滚应用前应先停止接受新拼单和调用并处理未完成订单；不能在有钱包流水后直接删除拼单表或回退数据库快照。

新增 `243_pool_credits.sql`：商品和订单增加配额方式、订阅类型与三项 `$` 额度；请求账本增加预占、实际金额及成员时间索引。数据库约束区分 Plus / Pro 窗口配置。原表数据保持 Token 模式，历史使用记录通过专属 Key 即时关联订单，无需大表回填。发货时若已识别账号为 Plus / Pro 且与商品不一致则拒绝。

## 拼团价格说明页

大厅顶部“查看拼团价格”进入 `/pool-orders/pricing`。登录用户通过 `/api/v1/pool-pricing` 读取与预占、结算同源的 `backend/internal/service/pool_pricing.json` 价表，展示每百万 Token 普通输入、缓存输入、缓存写入、输出价格及长上下文档位，附官方来源、核对日期、扣额示例、Plus / Pro 规则与使用记录入口。

当前价表核对日期为 2026-09-09，GPT-5.6 Sol 使用官方促销价。该文件是经核对发布的生效快照，不宣称自动同步官网。运营更新需核对官方 Standard 价格与模型说明、更新版本、测试并发布全部服务实例。页面和后端不读取普通中转渠道覆盖价。未单列缓存价的模型，如果上游仍返回缓存用量则按普通输入价计量，页面明确标注。价表表示计量价格，不承诺账号支持所有模型。

仅 `$` 拼单设置 Standard 计费上下文，异步使用记录继承该上下文；历史 Token 订单不改变计费。仅接纳已收录模型及其明确日期快照，未知型号不按相近名称猜价。路由到未收录模型时不猜测实际费用，保留预占待核对。标准价口径不加 Fast 倍率，也不应用 Flex / Batch 折扣；不重复扣钱包。
