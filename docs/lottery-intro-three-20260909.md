# 抽奖动画与账号前三次概率

本轮为本地改造，不部署生产，不修改线上活动开关或概率。

## 追加确认

- 每个账号历史前 3 次已完成抽奖使用独立高概率，第 4 次起恢复当天普通规则。
- 首三次基础概率：无奖 29.9%、1 额度 60%、5 额度 10%、10 额度 0.05%、20 额度 0.03%、50 额度 0.015%、100 额度 0.005%。
- 次数按全部历史抽奖流水累计，包含上线前记录、管理员抽奖和无奖，跨天不重置。失败、回滚或同一请求重试不额外计数。
- 原有普通概率及管理员次日普通概率设置不被覆盖；前三次规则目前为独立固定规则，在管理页只读展示。
- 每日全站 100 额度硬上限、超过剩余预算的奖项转无奖、预算耗尽结束活动等保护不变。前三次高概率不是保底奖励，会更快消耗每日预算。
- 普通用户仍须累计有效人民币实付充值满 10 元，每天北京时间 10:00–11:00 仅一次；管理员已启用的独立重复参与例外保持不变。
- 普通参与页不返回或展示内部概率、次数加成配置、预算或预算变化规则，也不承诺固定中奖率。

## 实现

- 前端复用现有 Vue/Tailwind 界面，通过 `useLotteryReveal` 将奖项逐个高亮，先快速轮转，再减速并停在服务器确认的真实奖项（包括无奖）。
- 正常模式至少轮转 1.4 秒，再减速、短暂停留并展开结果；请求迟迟未返回时保持等待，不提前生成结果。
- 按钮在请求和动画完成前保持禁用，避免重复提交。管理员未知结果重试继续复用原 UUID。
- 请求失败会取消动画并恢复服务器状态；组件卸载时清理计时器、解除待完成动画，避免残留回调。
- 系统减少动态效果时跳过轮转，收到真实结果后直接展示；仍保留请求等待与防重复保护。
- 新增迁移 `239_lottery_intro_draws.sql`，只扩展抽奖流水，不修改支付订单和既有余额。
- 在预算行、用户行锁保护下查询最多 3 条历史记录，判定本次专属序号；数据库部分唯一索引防止同一账号重复出现专属第 1/2/3 次。
- 前三次随机范围为 `[0,100000)`，保留 0.015% 与 0.005% 精度；普通规则继续使用 `[0,10000)`。两者均使用后端密码学安全随机源。
- 每笔新流水保存 `intro_draw_number` 和 `probability_weights` 快照；序号 0 表示普通规则，旧记录维持原状并自然占用历史次数。
- 管理页新增前三次概率说明和流水规则列；普通用户 DTO 继续通过白名单隔离内部数据。
