# OpenAI API Key 账号 HTTP/1.1 灰度试验

## 目的与边界

部分真实请求写入上游很快，但接收首响应头等待数十秒。该证据尚不足以区分上游入口、内部转发和回程，也没有证明 HTTP/2 是根因。本试验提供可按账号回退的连接协议选择，用真实流量验证本站侧调整是否有效。

仅当账号为 OpenAI 平台、API Key 类型，并且 `extra.openai_http_transport` 精确为字符串 `http1` 时，核心 OpenAI 转发使用 HTTP/1.1。未设置、未知值、OAuth 和其他平台保持原行为。

新协议复用现有 OpenAI 超时与连接池设置，通过既有协议标识隔离 H1/H2 客户端。请求内容、模型、计费、重试和响应数据处理不变。此开关不涵盖独立账号测试入口、WebSocket 或插件自有传输；验证协议必须查看真实请求，不能仅使用后台测试按钮。

## 灰度与回退

先发布默认关闭的代码，只对一个低流量 CallAI 账号开启，另一账号保持对照。保存原字段是否存在及原值，修改时仅更新这一字段，并投递 `account_changed` 事件刷新调度快照。禁止覆盖整个账号 extra。

上线前备份现有版本与配置，保留 `GOMEMLIMIT=1GiB` 和既有活动 Swap。候选通过健康、版本和资源检查后平滑切流，旧连接未结束时保留实例，不强制停止。若出现新协议连接失败、持续错误增长或资源恶化，优先恢复单账号字段并刷新快照；需要版本回退时沿用平滑发布流程，不恢复整库。

## 验收与效果口径

- 定向测试验证默认和 OAuth 隔离、超时策略保留、连接池隔离、TLS 实际协商 HTTP/1.1，以及 EOF 前首个流式数据块可读。
- 发布后以版本、健康检查和真实请求 `http_protocol` 确认实现已生效。
- 从用量表按固定时间窗统计首字中位数、P90、30 秒以上数量，并按模型、流式状态、输入/缓存量及可用的推理强度分层。另查错误尝试与重试，不能仅看成功请求。
- 慢成功与错误才记录的诊断日志不能计算无偏成功率或全量延迟分位数；用量耗时也不包含此前失败尝试。两账号流量并非随机分组，不凭一两笔快请求宣称因果或扩大灰度。
- 优先观察自然流量，不重放客户内容，不额外产生付费探测，不向供应商发送消息。
