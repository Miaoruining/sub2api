# 自动分组密钥与模型广场

## 本次范围

在现有 Sub2API 上增量增加自动分组密钥，不迁移 New API 数据库、不替换现有账户和余额系统。参考 New API 的卡片式模型展示、按顺序跨组选择以及选中组后重新计算计费上下文；Vue 前端仍复用本项目组件，不直接混入 React 代码。

旧密钥默认 `auto_group=false`，固定分组、价格、套餐、URL 和密钥字符串保持原样。仅主动启用自动分组的密钥使用新路由。

## 管理员配置

1. 保持 GPT 上游账号在 OpenAI 分组、Claude 上游账号在 Anthropic 分组；自动路由只在同一平台的组之间切换，不把分组名称当作平台判断依据。
2. 在账号配置明确的 `model_mapping`，或启用分组自定义模型清单并填写精确模型名称。空映射的透传账号不会自动获得框架默认模型列表，单独的通配符不生成可选模型。
3. 为分组配置价格渠道、倍率、用户专属倍率和套餐权限。同一公开模型在各组保持调用语义一致，不应把一个模型名映射到另一型号来隐藏降级。
4. 用分组排序控制尝试顺序：`sort_order` 升序，同序按分组 ID 升序。现有组内调度策略保留；本版不是按最低价格自动排序。每个请求最多尝试 8 个候选组。
5. 用户创建或编辑密钥时勾选“自动分组”。服务端拒绝同时指定 `auto_group=true` 和固定 `group_id`。

“全部模型”指当前用户有权限且已明确接入的模型，不包括未授权专属组、无有效订阅的订阅组、已停用组、无可调度账号的组或被价格渠道限制的模型。现有 Composite 组合组不进入自动组目录，继续使用固定组密钥。

## 路由与结算

每次尝试都重新鉴权、读取目标组和用户权限，再走该组原有的订阅、余额、限流、调度及协议处理链。目标组只绑定在本次请求的 APIKey 副本上，不修改数据库中的密钥分组或鉴权缓存。

纯容量不足、明确可重试的上游限流/服务端故障和账号级凭证故障可以触发切组。普通参数错误、安全策略拒绝、余额不足等不会被笼统当作换组理由。每个目标组均继续执行自己的权限检查。

成功请求的基础模型价格、专属倍率、分时/阶梯和图片计费规则、套餐结算及用量日志都取实际选中的组。失败后从 A 切到 B，不沿用 A 的价格。例：B 的按次价格为 $0.20、用户在 B 的倍率为 0.5，实扣 $0.10。未发生上游用量的容量选择失败不生成成功扣款；已经发生的上游用量仍遵循原有异常用量结算策略。

成功响应头 `X-Sub2API-Group-ID` 可帮助排查实际命中的组，最终账务以用量日志为准。对 HTTP Responses 的 `previous_response_id`，逐组执行原有用户/密钥所有权检查，只在拥有该响应的组继续请求。

## 协议边界

当前覆盖现有路由中的同步 JSON 请求，包括 Messages、Chat Completions、Responses（含 compact/input_tokens）、Embeddings、JSON 图片生成，以及 Gemini generateContent/streamGenerateContent/countTokens。具体平台与账号仍须支持相应端点，模型在目录中出现不代表它支持所有协议。

SSE 成功响应立即透传；一旦开始输出、显式 Flush/Hijack，或错误响应超过 64 KiB 缓冲上限，就不再跨组重放。不会把两个流拼到一起。

WebSocket、异步任务及状态查询、文件上传、`background=true` 暂不支持自动密钥，返回明确错误；这些功能继续使用固定分组密钥。自动密钥的手动配置界面不提供 Codex WebSocket 选项。

## 模型目录与展示

- 自动密钥 `/v1/models` 与路由使用同一严格目录，去重后只显示授权模型；跨平台歧义别名不展示、不猜测。
- Codex 清单只包含 OpenAI 候选模型，按真实候选组账号汇总能力，采用现有能力交集逻辑，不读取虚拟零号分组。CC Switch 的自动 Codex 导入必须成功取得清单后才能选择模型。
- 广场默认卡片视图，按供应商、计费方式、分组筛选。相同平台、名称和计费单位的模型合并，展示标准时段实价区间；详情复用已有价格表，保留缓存、阶梯和分时规则。不虚构模型简介和能力标签。
- 登录用户默认只看“我的自动密钥可用模型”，取消勾选可回到原价目目录。匿名视图是价格橱窗，不表示匿名可调用。

## 验证与发布

新增测试覆盖：真实鉴权链跨组重试、请求体与错误头隔离、已开始流不重放、切组前权限撤销、严格目录与 Codex 清单、密钥更新列掩码、结算服务实际组价格/用户倍率/扣款指令、数据库读写与互斥约束、卡片筛选和 CC Switch 导入。

```sh
# frontend

node node_modules/vite/bin/vite.js build --config vite.config.ts
```

数据库迁移 `235_api_key_auto_group.sql` 仅增加默认 false 的字段与互斥约束，不重写旧密钥。先在隔离环境验证迁移，再更新全部后端节点，最后向少量测试密钥开放。不能在仍有旧后端节点的混合版本阶段开放自动密钥。

本轮没有替换正在运行的 Sub2API 后端、没有生产部署，也没有用真实付费上游进行扣款联调。`127.0.0.1:31335` 是新前端经只读代理读取旧本地后端公开价目的外观预览，不是新路由的联调环境；代理只放行公开设置与模型广场 GET 请求，不允许登录或业务写入。自动扣费发布前仍需对真实账号、套餐、限流和上游故障进行小流量验收。

回滚时先把所有自动密钥改为明确的固定组或停用，再回退应用版本；不要直接将自动密钥当作旧版未分组密钥运行，也不要删除密钥/余额表。新增字段可保留，不需要破坏性数据库回滚。
